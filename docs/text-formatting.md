# Оформление текста

Раздел отвечает на вопросы: как оформлять заголовки, списки, таблицы, выделения, примечания, ссылки, изображения и элементы интерфейса.

## ОФ-1. Заголовки {#of-1}

- Заголовок кратко называет содержание раздела. В инструкциях заголовок начинается с глагола в инфинитиве: «Создать задачу», «Настроить уведомления».
- Пишем с прописной буквы только первое слово и имена собственные: «Настройка интеграции с GitHub».
- В документе один заголовок первого уровня. Уровни не пропускаем: после `##` идёт `###`, а не `####`.
- Используем не больше трёх уровней заголовков. Если нужен четвёртый, разделите документ.
- Не ставим точку в конце и не нумеруем заголовки вручную.

<!-- textlint-disable -->

| Не пишем | Пишем |
| --- | --- |
| Создание Новой Задачи. | Создать задачу |
| Как мне поменять пароль? | Изменить пароль |

<!-- textlint-enable -->

Проверка: линтер (уровни, точка в конце), ревью.

## ОФ-2. Абзацы {#of-2}

Абзац раскрывает одну мысль и состоит из 1–5 предложений. Между абзацами — пустая строка. Не используем отступы и разрывы строк внутри абзаца.

Проверка: линтер, ревью.

## ОФ-3. Списки {#of-3}

- **Нумерованный список** используем для последовательных шагов, когда порядок важен.
- **Маркированный список** используем для перечислений, когда порядок не важен.
- Перед списком ставим вводное предложение с двоеточием или заголовок.
- Если пункты — отдельные предложения, начинаем их с прописной буквы и ставим точку в конце.
- Если пункты — короткие фразы, продолжающие вводное предложение, начинаем со строчной буквы и разделяем точкой с запятой. В последнем пункте ставим точку.
- В списке не меньше двух пунктов. Вложенность — не больше двух уровней.

Проверка: линтер (разметка списков), ревью.

## ОФ-4. Таблицы {#of-4}

- Используем таблицы для данных, которые сравнивают по нескольким признакам: параметры, права доступа, коды ошибок.
- У каждой таблицы есть строка заголовков. Заголовки столбцов — существительные в именительном падеже.
- Не оставляем пустые ячейки: пишем «—» или «Нет».
- Не вставляем в ячейки списки и длинные абзацы. Если текст не помещается, используйте подразделы.

Проверка: линтер (формат таблицы), ревью.

## ОФ-5. Выделение текста {#of-5}

| Что выделяем | Как выделяем | Пример |
| --- | --- | --- |
| Элементы интерфейса: кнопки, пункты меню, поля | Полужирный | Нажмите **Сохранить** |
| Путь по меню | Полужирный, разделитель `→` | **Настройки → Уведомления** |
| Команды, код, имена файлов, значения параметров | Моноширинный шрифт | `npm run lint`, `mkdocs.yml` |
| Клавиши и сочетания клавиш | Моноширинный шрифт, знак `+` | `Ctrl+Enter` |
| Новый термин при первом упоминании | Курсив | *Спринт* — период работы команды |

Не используем для выделения подчёркивание, цвет и «ЗАГЛАВНЫЕ БУКВЫ». Полужирный не используем для «важных мыслей» в обычном тексте — для этого есть примечания.

Проверка: линтер (слова заглавными буквами), ревью.

## ОФ-6. Примечания и предупреждения {#of-6}

Выносим в блоки только то, что читатель не должен пропустить. Используем три типа блоков:

| Тип блока | Когда используем |
| --- | --- |
| `note` — Примечание | Дополнительная полезная информация |
| `tip` — Совет | Способ сделать задачу быстрее или удобнее |
| `warning` — Внимание | Риск потери данных, необратимое действие, ограничения безопасности |

/// warning | Внимание
Не ставьте больше двух блоков подряд и больше трёх блоков на один экран текста. Если всё выделено, ничего не выделено.
///

Синтаксис блоков описан в разделе [Правила работы с Markdown](markdown.md).

Проверка: ревью.

## ОФ-7. Ссылки {#of-7}

- Текст ссылки описывает, куда она ведёт: «подробнее в разделе [Шаблоны](doc-templates/index.md)».
- Ссылки на внутренние страницы делаем относительными путями к файлам `.md`.
- Внешние ссылки ведут на официальные источники. Не вставляем «голые» адреса в текст, кроме случаев, когда адрес нужно скопировать.

Проверка: линтер (битые ссылки при сборке), ревью.

## ОФ-8. Изображения и скриншоты {#of-8}

- Добавляем скриншот, только если без него сложно найти элемент интерфейса. Не дублируем скриншотом то, что описано текстом.
- Скриншот показывает только нужную область окна. Важные элементы выделяем красной рамкой толщиной 2 px.
- У каждого изображения есть альтернативный текст, который описывает его содержание.
- Персональные данные на скриншотах заменяем тестовыми или размываем.
- Файлы изображений храним в папке `img` рядом с документом в формате PNG или SVG. Имена файлов — латиницей в kebab-case: `task-create-form.png`.

Проверка: линтер (альтернативный текст), ревью.

## ОФ-9. Элементы интерфейса {#of-9}

- Названия элементов интерфейса пишем точно так же, как в продукте, с сохранением регистра, и выделяем полужирным без кавычек.
- Тип элемента не указываем, если он понятен: «нажмите **Сохранить**», а не «нажмите на кнопку **Сохранить**».
- Для действий используем глаголы: «нажмите» для кнопок, «выберите» для списков и пунктов меню, «введите» для полей, «установите флажок» для чекбоксов.

<!-- textlint-disable -->

| Не пишем | Пишем |
| --- | --- |
| Кликните по кнопке "Сохранить". | Нажмите **Сохранить**. |
| Отметьте галочку «Напоминать». | Установите флажок **Напоминать**. |

<!-- textlint-enable -->

Проверка: линтер (словарь терминов), ревью.
