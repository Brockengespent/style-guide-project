# Словарь и глоссарий

Раздел состоит из двух частей. Словарь говорит, какие слова мы используем, а какие заменяем. Глоссарий объясняет термины продукта. Часть словаря проверяет линтер. Замены с автоисправлением лежат в файле `prh.yml`, проверки жаргона и канцелярита — в правиле `.textlint/rules/ru-style.js`.

## ГЛ-1. Словарь: пишем и не пишем {#gl-1}

### Канцелярит и лишние слова

<!-- textlint-disable -->

| Не пишем | Пишем |
| --- | --- |
| данный, данная, данное | этот, эта, это |
| осуществлять, производить (действие) | выполнять или конкретный глагол |
| является | это, или перестройте предложение |
| для того чтобы | чтобы |
| в случае если | если |
| необходимо | нужно |
| в настоящее время | сейчас |
| стоит отметить, как известно, в целом | удалите |

## ГЛ-2. Глоссарий продукта {#gl-2}

| Термин | Определение |
| --- | --- |
| Доска | Рабочее пространство команды, на котором задачи разложены по колонкам. |
| Задача | Единица работы с исполнителем, сроком и статусом. |
| Колонка | Этап работы на доске, например «В работе» или «Готово». |
| Проект | Набор досок и участников, объединённых общей целью. |
| Спринт | Период работы команды фиксированной длины, обычно две недели. |
| Участник | Пользователь, у которого есть доступ к проекту. |
| Владелец проекта | Участник, который управляет настройками и составом проекта. |

## ГЛ-3. Как добавить слово или термин {#gl-3}

1. Добавьте строку в нужную таблицу этого раздела.
2. Если замену можно проверить автоматически, добавьте правило в файл `prh.yml`.
3. Запустите `npm run lint` и убедитесь, что новые правила не дают ложных срабатываний.
4. Создайте Pull Request с типом коммита `docs(glossary)`.
