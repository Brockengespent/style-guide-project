# Правила работы с Markdown

Раздел отвечает на вопросы: как размечать документы, называть файлы и использовать расширения MkDocs. Большинство правил проверяет markdownlint, настройки лежат в файле `.markdownlint-cli2.jsonc`.

## MD-1. Файлы и папки {#md-1}

- Один документ — один файл с расширением `.md`.
- Имена файлов и папок пишем латиницей в нижнем регистре, слова разделяем дефисом: `release-notes.md`, `api-method.md`.
- Изображения храним в папке `img` рядом с документом.
- Каждую новую страницу добавляем в навигацию `nav` в файле `mkdocs.yml`.

Проверка: ревью, сборка `mkdocs build --strict`.

## MD-2. Заголовки {#md-2}

- Используем только заголовки с решётками (ATX): `## Заголовок`. Подчёркивание `===` и `---` не используем.
- Первая строка файла — заголовок первого уровня `#`.
- Для правил и разделов, на которые часто ссылаются, задаём постоянный якорь: `## ОП-2. Кавычки {#op-2}`.

Проверка: линтер (MD001, MD003, MD025, MD041).

## MD-3. Пустые строки и пробелы {#md-3}

- Заголовки, списки, таблицы, блоки кода и примечания отделяем пустыми строками.
- Не оставляем пробелы в конце строк и несколько пустых строк подряд.
- Файл заканчивается одним переводом строки.

Проверка: линтер (MD009, MD012, MD022, MD031, MD032, MD047).

## MD-4. Списки {#md-4}

- Маркер маркированного списка — дефис `-`.
- Нумерованный список размечаем последовательными номерами `1.`, `2.`, `3.`.
- Вложенный список сдвигаем на 4 пробела — этого требует MkDocs.

```markdown
1. Откройте доску.
2. Нажмите **Создать задачу**.
    - Если кнопки нет, проверьте права доступа.
3. Заполните поля и нажмите **Сохранить**.
```

Проверка: линтер (MD004, MD007, MD029).

## MD-5. Код и команды {#md-5}

- Код, команды и примеры вывода оформляем блоками с тремя обратными апострофами и указываем язык: `bash`, `json`, `yaml`, `markdown`.
- Команды в блоке пишем без приглашения `$`, чтобы их было удобно копировать.
- Однострочные фрагменты кода внутри текста оформляем одинарными обратными апострофами.

```bash
npm run lint
mkdocs serve
```

Проверка: линтер (MD014, MD040, MD046).

## MD-6. Выделения {#md-6}

- Полужирный размечаем двумя звёздочками `**текст**`, курсив — одной `*текст*`.
- Не используем HTML-теги для оформления. Исключение — комментарии для управления линтером.

Проверка: линтер (MD033, MD049, MD050).

## MD-7. Примечания {#md-7}

Примечания оформляем блоками расширения `pymdownx.blocks.admonition`. Тип блока пишем латиницей, заголовок — по-русски:

```markdown
/// note | Примечание
Текст примечания.
///
```

Так текст внутри блока проверяется линтером, в отличие от блоков с отступом.

Проверка: ревью.

## MD-8. Таблицы {#md-8}

- Таблицы размечаем с вертикальными чертами в начале и в конце строки.
- Строку-разделитель пишем как `| --- | --- |`.

Проверка: линтер (MD055, MD056).

## MD-9. Примеры нарушений {#md-9}

Примеры того, как писать не нужно, мы приводим в таблицах «Не пишем / Пишем». Чтобы линтер не считал их ошибками, оборачиваем такие таблицы в комментарии:

```markdown
<!-- textlint-disable -->

| Не пишем | Пишем |
| --- | --- |
| Данный раздел | Этот раздел |

<!-- textlint-enable -->
```

Не отключайте проверки для обычного текста. Если правило мешает, обсудите его изменение в Pull Request.

Проверка: ревью.
